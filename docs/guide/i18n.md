# Internationalisation and collection text

```html
<select (change)="setLocale($event.target.value)">
  <option *for="l of availableLocales; key: l.code" [value]="l.code"
          [.selected]="l.code === locale">{{ l.label }}</option>
</select>
```

That is the whole language switch. Every string in every mounted component changes when
it fires, with no reload, no per-locale bundle, no re-bootstrap and no subscription in
any component — `t()` reads a message table held in a signal, so a component that
renders a translated string has subscribed by doing so. This is the one capability the
architecture gets for free that Angular cannot have: `$localize` substitutes at build
time and therefore needs one deployment per locale.

- **Message tables** are JSON, nested or flat, flattened to dotted keys at load. A key
  beginning with `$` is a note to translators — JSON has no comments — and is skipped by
  both the runtime's `flatten` and the verifier's key collector, which is what lets the
  tool claim it flattens exactly as the runtime does.
- **Bundles merge**, so a micro-frontend ships its own translations and registers them
  when it loads; the shell's manifest does not know its keys exist.
- **Fallback is per key, not per locale.** `example/i18n/ar.json` is deliberately
  incomplete; the rest renders in English rather than the page reverting wholesale.
- **Plurals come from `Intl.PluralRules`.** English declares `one`/`other` for a key;
  Arabic declares `zero`/`one`/`two`/`few`/`many`/`other` for the same key at no extra
  cost.
- **`Intl` does all formatting**, memoised per locale and reactive: `num`, `cur`, `dt`,
  `rel`. Currency stays a property of the amount, never of the locale. Italian CLDR sets
  `minimumGroupingDigits: 2`, so `1234` renders as `1234` in Italian and `1,234` in
  English — nobody hand-rolling number formatting gets that right.
- **RTL is `dir` from a computed signal** plus Tailwind's logical utilities (`ms-`,
  `me-`, `ps-`, `pe-`). There is no per-locale stylesheet.
- `npm run verify` lints the translations: a key present in a translation but absent
  from the default locale fails the build, because it renders correctly in exactly one
  language and as a raw key everywhere else. Untranslated keys are counted, not failed.

**Store keys, not sentences.** A string put into a signal via `t()` keeps the sentence,
so it does not follow a language change. Anywhere a value outlives a render, store the
key.

## The collection's own text

No element in `source/components` contains an English string. Two kinds of text, and
the line between them is: **a string that names the data is a property; a string that
names the interaction is standard text.**

A label naming this screen's data arrives as a property, so the consumer passes `t('…')`
and it follows a language change like everything else:

```html
<ui-sidebar-toggle label="{{ t('a11y.toggleSidebar') }}">
```

What an element says about *itself* — "Sort ascending by", "Next page", "Clear" — is
named by `source/components/internal/text.js` instead, one key per string under
`ui.table.`, `ui.filter.`, `ui.combobox.` and `ui.dateRange.`, and the application's
message bundle answers:

```json
{ "ui": { "table": { "previous": "Previous page", "empty": "No rows found." } } }
```

```html
<ui-table [.rows]="rows" caption="{{ t('nav.peopleStaff') }}"></ui-table>
```

That is the whole binding. A table owns pagination, sorting and a column chooser, and
therefore about twenty accessible names; a property per string meant every screen
repeated every one of them and a twenty-first affordance could not be added without
editing every caller.

The resolver defaults to the message table, so a locale change re-resolves every
mounted element with no subscription anywhere. An application whose copy lives
elsewhere replaces the seam once:

```js
configureCollectionText({ resolve: (key) => myDictionary[key] });
```

A missing message renders as its key, which is visible in the page and counted by
`npm run verify`. The empty string is *not* missing — it is a deliberate "no words here",
which is how `ui.filter.from` and `ui.filter.to` emptied make a range chip read
`3/3 – 3/7`. Three per-instance overrides survive, because their wording names the
data: `ui-table.emptyLabel`, `ui-combobox.notFoundLabel` and `ui-combobox.addTagLabel`.
Each falls back to its standard key when left empty.
